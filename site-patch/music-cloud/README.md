# Облако VIT Music — правка для viton13.com

Приложение VITON13 уже умеет загружать свою музыку в «VIT Music» и хранить её **на этом Mac** — бесплатно, без сайта.
Эта правка добавляет второй уровень — **«В облаке VITON13»**: личная копия трека в хранилище сайта, чтобы музыка была
в интернете и на других устройствах с тем же VITON ID. Пока правка не выложена, приложение пишет:
«Облако VIT Music появится после обновления viton13.com» — и ничего не ломается.

## Что меняется

Новые файлы (старые не трогаются):

| Файл | Что делает |
|---|---|
| `lib/music-cloud.mjs` | правила и лимиты: какие файлы принимаются, квоты, дневной лимит скачиваний |
| `app/api/music-cloud/_shared.js` | вход по VITON ID, доступ к Firestore и бакету |
| `app/api/music-cloud/route.js` | `GET` — мои треки в облаке и сколько места занято; снимает брошенные загрузки старше 2 часов |
| `app/api/music-cloud/uploads/route.js` | `POST` — резервирует место (транзакция) и выдаёт ссылку возобновляемой загрузки ровно на один объект |
| `app/api/music-cloud/[trackId]/complete/route.js` | `POST` — проверяет, что файл дошёл целиком и это аудио, переводит резерв в занятое место; маленькая обложка (≤ 300 КБ) хранится на документе трека |
| `app/api/music-cloud/[trackId]/url/route.js` | `GET` — подписанная ссылка на 15 минут, только владельцу; каждая ссылка учитывается в дневном лимите |
| `app/api/music-cloud/[trackId]/cover/route.js` | `GET` — обложка (из Firestore, без скачивания из хранилища) |
| `app/api/music-cloud/[trackId]/route.js` | `PATCH` — переименовать; `DELETE` — удалить файл, документ и освободить место |

Данные:

- Файлы: бакет `FIREBASE_STORAGE_BUCKET`, путь `music-cloud/{uid}/{trackId}.{mp3|m4a|…}`. Бакет закрытый: публичных ссылок нет.
- Firestore: `vitonMusicCloud/{uid}` (сколько занято), `vitonMusicCloud/{uid}/tracks/{trackId}` (трек),
  `vitonMusicCloudTotals/project` (сколько занято на весь проект и сколько скачано сегодня).
- Все проверки — на сервере: сессия VITON ID (`getSessionUser`), `validateMutationRequest` для записи,
  `consumeRateLimit` (60 загрузок в день на человека), транзакции для квот.

Приложение ходит сюда через тот же мост, что и «Сообщения» (`server/worlds/messages.mjs`): запросы идут со страницы
сайта с его собственной сессией. Сами байты уходят прямо в хранилище по выданной ссылке и возвращаются по подписанной ссылке.

## Почему нет публичных ссылок

Облако личное: трек видит и скачивает только тот, кто его загрузил. Если сделать «поделиться музыкой со всеми»,
сайт начнёт раздавать чужие записи — это вопрос авторских прав и жалоб правообладателей. Поэтому ссылки — только
подписанные, на 15 минут и только владельцу. В приложении написано: «Загружайте музыку, на которую у вас есть права».

## Сколько это стоит — бесплатный уровень (проверено 13.11.2026)

Источник: https://firebase.google.com/pricing и https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024

- **Cloud Storage for Firebase с 3 февраля 2026 работает только на тарифе Blaze** (оплата по факту). На Spark бакеты недоступны.
- Бесплатный объём на Blaze зависит от бакета:
  - старый бакет `*.appspot.com` — **5 ГБ хранения, 1 ГБ скачиваний в день, 20 000 загрузок и 50 000 скачиваний в день**;
  - новый бакет `*.firebasestorage.app` (только регионы us-central1, us-west1, us-east1) — **5 ГБ-месяцев хранения,
    100 ГБ скачиваний в месяц, 5 000 загрузок и 50 000 скачиваний в месяц**.
- Firestore (документы треков): 1 ГиБ хранения, 50 000 чтений и 20 000 записей в день — облако музыки тратит на трек
  примерно 4 записи при загрузке и 2–3 чтения при прослушивании.

Чтобы первый месяц обошёлся в 0, в `lib/music-cloud.mjs` стоят защитные лимиты (каждый меняется переменной окружения):

| Лимит | По умолчанию | Переменная |
|---|---|---|
| Место на человека | 2 ГБ | `MUSIC_CLOUD_USER_QUOTA_BYTES` |
| Всё облако проекта | 4,5 ГБ (ниже 5 ГБ бесплатных) | `MUSIC_CLOUD_PROJECT_CAP_BYTES` |
| Скачиваний на весь проект в день | 900 МБ (ниже 1 ГБ/день у `appspot.com`) | `MUSIC_CLOUD_DAILY_DOWNLOAD_BYTES` |
| Скачиваний на человека в день | 300 МБ | `MUSIC_CLOUD_USER_DAILY_DOWNLOAD_BYTES` |
| Загрузок на человека в день | 60 | `MUSIC_CLOUD_UPLOADS_PER_DAY` |
| Размер трека | 50 МБ | — |

Средний трек — 5–10 МБ: в 4,5 ГБ помещается примерно 450–900 треков на весь проект, 900 МБ в день — это около
100–180 прослушиваний. Каждое прослушивание из облака берёт новую ссылку и считается целым файлом (с запасом).
Если бакет `*.firebasestorage.app`, дневной лимит скачиваний можно поднять до ~3 ГБ (100 ГБ в месяц),
но тогда стоит следить за 5 000 загрузок в месяц.

Если облако заполнено, приложение говорит «Облако VITON13 сейчас заполнено. Трек остаётся на этом Mac», если исчерпан
дневной лимит — «На сегодня лимит облака исчерпан». Деньги сверх бесплатного уровня не тратятся.

## Подписка VIT

Пока подписки живут в приложении VITON13 (а не на сайте), облако открывается только подписчикам **на стороне
приложения** (`can(user, 'music.cloud')` в `server/worlds/music.mjs`). Сайт сейчас пускает любого вошедшего по VITON ID —
обойти это может только тот, кто сам переделает открытый код приложения, а квоты всё равно держат расходы.
Когда подписки и оплата переедут на viton13.com, в `context()` из `_shared.js` нужно добавить одну проверку:
у пользователя есть активная подписка VIT (поле в его профиле) — иначе `error("SUBSCRIPTION_REQUIRED", 402)`.

## Как выложить

1. Убедиться, что проект на тарифе **Blaze** и задана переменная `FIREBASE_STORAGE_BUCKET` (она уже используется сайтом
   для VIT MARKET). Посмотреть, какой бакет: `*.appspot.com` или `*.firebasestorage.app` — от этого зависят лимиты выше.
2. Положить файлы из этой папки в те же пути сайта (overlay-релиз, как обычно; рабочую копию сайта целиком не выкладывать).
3. Выложить сайт. Новых индексов Firestore не нужно (простая сортировка по `createdAt` внутри подколлекции).
4. Проверить в приложении VITON13 (окно приложения, вход по VITON ID с подпиской): «VIT Music» → «Мои треки» →
   у трека «⋯» → «Загрузить в облако VITON13». Карточка «В облаке VITON13» покажет занятое место.

Откат — удалить эти файлы и выложить снова; данные в бакете лежат в `music-cloud/` и удаляются одной командой
`gsutil -m rm -r gs://<бакет>/music-cloud/` (и коллекции `vitonMusicCloud*` в Firestore).
