# Комнаты для «Встреч» на viton13.com

Обновление сайта, которое нужно, чтобы во «Встречах» приложения VITON13 люди с разных компьютеров находили друг друга.

## Что это и почему так

- **Видео и звук идут напрямую между участниками** (WebRTC, каждый с каждым, до 6 человек). Через сайт и сервер не проходят ни картинка, ни звук, ни фильм. Поэтому трафик сервера не растёт.
- **Сайт только знакомит устройства.** Он хранит маленький документ комнаты (код, кто внутри) и короткий «почтовый ящик», куда устройства кладут друг другу предложение соединиться (offer) и ответ (answer). После соединения всё остальное идёт по прямому каналу между участниками: чат, реакции, общая пауза и перемотка фильма, показ экрана.
- **Вход — только по VITON ID**, той же сессией, что у сообщений. Писать и читать сигналы могут только участники комнаты. Каждый читает только адресованное ему.
- **Всё исчезает само:** комната живёт 12 часов, сигналы — 10 минут (поле `expiresAt` + TTL-политика Firestore).
- Прямой доступ к коллекциям из браузера уже закрыт правилами `firestore.rules` («всё через API»), менять их не нужно.

## Файлы (кладутся в корень проекта сайта с теми же путями)

| Файл | Что делает |
|---|---|
| `lib/rtc-rooms.mjs` | общие правила: код из 6 знаков без 0/O/1/I/L, до 6 человек, сроки жизни, лёгкий лимит частоты опроса в памяти |
| `app/api/rtc/rooms/route.js` | `POST` — создать встречу, создатель сразу внутри |
| `app/api/rtc/rooms/[code]/route.js` | `GET` — название и кто уже внутри (для экрана перед входом) |
| `app/api/rtc/rooms/[code]/presence/route.js` | `POST {action: join \| heartbeat \| leave}` — войти, отметиться (раз в 2 минуты), выйти |
| `app/api/rtc/rooms/[code]/signal/route.js` | `POST {to, type: offer\|answer\|candidate\|bye, data}` — оставить сигнал участнику; `GET ?since=&members=1` — забрать свои сигналы (и иногда список участников) |
| `app/api/rtc/rooms/[code]/_shared.js` | общая проверка сессии и кода комнаты |

Стиль тот же, что у `app/api/messages/*`: `validateMutationRequest` на запись, `getSessionUser`, `consumeRateLimit` на создание, вход и сигналы, ответы `withNoStore`.

Данные в Firestore:
- `vitonRtcRooms/{CODE}` — `{ code, title, hostId, createdAt, expiresAt, members: { uid: { name, vitonId, avatarUrl, joinedAt, seenAt } } }`
- `vitonRtcRooms/{CODE}/inbox/{uid}/rtcSignals/{auto}` — `{ from, type, data, createdAt, expiresAt }`

Запрос опроса — диапазон по одному полю (`createdAt`), составной индекс не нужен.

## Сколько это стоит — укладываемся в бесплатный тариф

Бесплатно у Firestore в день: **50 000 чтений, 20 000 записей, 20 000 удалений**, 1 ГБ хранения — на весь проект.

Одна встреча вдвоём, час (каждый запрос к API ещё читает профиль в `getSessionUser` — это учтено):

| Что | Записи | Чтения |
|---|---|---|
| создать комнату, войти двоим | ~6 | ~8 |
| знакомство: offer + answer (кандидаты ICE собираются заранее и едут внутри offer — отдельных записей нет) | ~4 | ~6 |
| отметки «я здесь» раз в 2 минуты | ~60 | ~120 |
| опрос: первые ~20 с раз в секунду, дальше раз в 5 с, список участников раз в 15 с | 0 | ~3 400 |
| **итого за час вдвоём** | **~70** | **~3 500** |

Это примерно **14 часов разговоров вдвоём в день** (или ~5 часов встречи вшестером) в бесплатном лимите чтений, а записи почти не тратятся. Хранение — килобайты: сигналы по ~7 КБ живут 10 минут. Видео, звук и фильмы на сайт не попадают совсем.

В проверке на копии сайта две встречи по двое дали **4 записи сигналов** (по одному offer и answer на пару).

Если позже встреч станет много, первое, что стоит сделать, — заменить опрос на поток событий (как `/api/messages/events`), тогда чтений станет в разы меньше.

## Связь в сложных сетях (TURN)

По умолчанию приложение использует только бесплатные публичные STUN-серверы (Google, Cloudflare). Этого хватает для большинства домашних и мобильных сетей, но примерно **10–20% сетей** (строгий корпоративный NAT, некоторые мобильные операторы) напрямую не соединятся — участник увидит «Нет связи — возможно, мешает сеть».

Это решает ретранслятор TURN. Его можно добавить позже без изменений сайта — только в `.env` приложения:

```
VIT_TURN_URL=turn:…:443?transport=tcp
VIT_TURN_USER=…
VIT_TURN_PASS=…
```

Например, бесплатный тариф Metered «Open Relay» — 20 ГБ ретрансляции в месяц. Через TURN идёт только трафик тех, кто иначе не соединился бы.

## Как выложить

1. Скопировать файлы из этой папки в проект сайта (`~/Documents/VITON13`) с теми же путями. Ничего существующего они не меняют.
2. Выложить как обычно (overlay-релиз), проверить, что `POST /api/rtc/rooms` без входа отвечает `401 VITON_ID_REQUIRED`.
3. Один раз включить автоудаление (TTL) по полю `expiresAt` для двух групп коллекций — в консоли Firebase (Firestore → TTL) или командой:

```
gcloud firestore fields ttls update expiresAt --collection-group=vitonRtcRooms --enable-ttl
gcloud firestore fields ttls update expiresAt --collection-group=rtcSignals --enable-ttl
```

Без TTL всё тоже работает: старые комнаты просто перестают открываться по сроку, а документы остаются лежать (они крошечные).

После выкладки «Встречи» в приложении заработают сами — до неё приложение честно пишет «Встреч на viton13.com ещё нет».
